# Accounting machine SDK contract pin

These three product clients cover **all 56** customer machine operations in the immutable production Accounting catalog and only the **12** synthetic operations in the isolated test catalog. The catalog count is derived from `operationId` values, not manually curated. They do not call the human Console, internal APIs, provider callbacks, or webhook delivery endpoints.

Source: `d0-api-standards` commit `a92a694a3f5201000feb9b02254d8f9bc66dc4ef`, Accounting bundles `2026-10-15-access-audit-release` and `2026-10-15-test-access-audit-release`. Canonical `public-openapi.json` SHA-256:

- production: `7bfa5ed6234f1303dc90edb7e65f4214f285217b36f814b4740fb77ff9ef2011`
- test: `84f95a57f78e344ec6a27607bf745676ae421d4a63e619f09378f0e483f72784`

The two hash-pinned public catalog files are vendored in `sdk/contracts` so SDK generation does not depend on private repository access. `generate.py` verifies both hashes before regenerating operation descriptors, TypeScript schema/request/result types, Python TypedDicts and named methods, and Go named wrappers. The Go schema/client model is regenerated with the repository-pinned `oapi-codegen v2.8.0`; its runtime `v1.7.0` and nullable `v1.2.0` match the Accounting service. All three were checked against their official GitHub latest releases on 2026-10-15. Do not edit generated files manually.

`go test ./sdk` compares every public operation and referenced component to the current runtime OpenAPI, allowing only the catalog's documented security-scheme narrowing and test-origin rewrite. A negative regression rejects the previous eight-grant limit. The Accounting SDK candidate is v0.1.1; shared auth remains v0.1.0 and the historical public Go v0.1.0 is untouched.

The clients select only the canonical production resource `https://api.d0.eu/accounting` or isolated test resource `https://api.test.d0.eu/accounting`, with `/v1` for HTTP. The shared machine transport from `d0-auth` commit `427beab15ee4ba6d6487a85120d920f028a1cee5` owns private-key JWT, DPoP proofs, nonce retry, token refresh, HTTPS and redirect rejection. The canonical Go distribution paths are `github.com/dev-null-GmbH/d0-sdk/accounting/go` and `github.com/dev-null-GmbH/d0-sdk/auth/go v0.1.0`; the local Go replace plus npm/Python source overrides make qualification reproducible in this sibling workspace. **Do not publish v0.1.1** until the public `d0-sdk` release assembly removes local overrides and qualifies every artifact. Never place signing keys in browser code.

Create the client for one profile and one `ten_` public tenant ID. An empty tenant is accepted only for `listTenants`/`createTenant` onboarding. Every mutation takes a caller-owned `Idempotency-Key` of 16–128 safe characters; preserve it on retry. `If-Match` values are passed through unchanged, with Go exposing the generated response headers and TypeScript/Python exposing the latest ETag. Amounts remain exact decimal **strings** in minor units. Success bodies use generated schema types; failures expose bounded status, problem type/title, and request ID without raw problem detail. Binary responses have a 512 MiB bound; ordinary responses have a 24 MiB bound. List operations expose opaque `nextCursor` values and bounded page helpers; asynchronous status reads have at-most-two-minute polling helpers. The fixtures create two accounts, an open period, and an unposted balanced draft in both profiles. They never post a Buchung or reach a live service.

Run `sdk/check.sh` from this checkout. Its local source qualification requires sibling `d0-auth` at the pinned machine transport surface. Full pull-request SDK compilation becomes a gate when the public auth source package/release pipeline is available.
